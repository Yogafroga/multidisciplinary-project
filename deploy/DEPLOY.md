# DEPLOY.md

Техническая инструкция по локальному развёртыванию проекта (backend + frontend) с использованием Docker.

Назначение: документ предназначен для ИТ-специалистов — содержит требования, конфигурации, команды для запуска, применения миграций и проверки работоспособности.

Содержание:
- Требования и подготовка окружения
- Получение кода
- Установка Docker
- Настройка переменных окружения (`backend/.env`, `frontend/.env`)
- Сборка и запуск сервисов (`docker compose`)
- Применение миграций (Alembic)
- Запуск фронтенда (dev/build)
- Проверка и отладка
- Удаление сервисов и данных
- Замечания для production

---

## Что нужно подготовить
- Компьютер с Windows 10/11, macOS или Linux.
- Доступ к интернету для скачивания Docker-образов.
- Права администратора для установки Docker.
- Рекомендуется 4+GB свободной RAM.

Если хотите, мы можем поставить Docker и настроить всё удалённо (по запросу).

Склонируйте репозиторий или распакуйте архив с кодом в рабочую директорию:

```bash
git clone <REPO_URL>
cd multidisciplinary-project
```

## 1. Установка Docker
Инструкция коротко — используйте официальный Docker Desktop.

- Windows: скачайте и установите Docker Desktop: https://www.docker.com/get-started
  - После установки перезагрузите компьютер и проверьте, что Docker запущен (иконка в трее).
  - Для стабильности на Windows рекомендуется включить WSL2 во время установки (инсталлятор предложит).

- macOS: скачайте Docker Desktop для macOS с той же страницы и установите.

- Linux (Ubuntu):

```bash
# пример для Ubuntu
sudo apt update
sudo apt install -y docker.io docker-compose
sudo systemctl enable --now docker
```

Проверьте работу Docker:

```bash
docker --version
docker compose version
```

Если команды работают — можно продолжать.

## Пояснение: что такое Docker и зачем он нужен
Docker — это инструмент, который упаковывает приложение и все его зависимости в «контейнер». Контейнеры изолированы и одинаково запускаются на разных компьютерах, поэтому мы даём заказчику набор команд, а не инструкции по установке окружения вручную.

Преимущества для заказчика:
- Быстрый запуск без установки Python/Postgres/Node.js локально.
- Повторяемость окружения: у вас и у разработчика одинаковая среда.
- Удобно запускать на сервере или в облаке.

## 2. Настройка переменных окружения (`backend/.env`)
В директории `backend` присутствует файл ` .env.example`. Скопируйте его в `backend/.env` и отредактируйте значения.

Windows (PowerShell):

```powershell
Copy-Item backend\.env.example backend\.env
notepad backend\.env
```

Linux / macOS:

```bash
cp backend/.env.example backend/.env
nano backend/.env
```

Ключевые переменные:
- `DATABASE_URL`: строка подключения к базе данных. Для запуска через docker-compose используйте:

```
DATABASE_URL=postgresql://postgres:postgres@db:5432/cattle_db
```

- `SECRET_KEY`: секретное значение для подписи токенов/шифрования.
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` и т.п.: задать только при использовании S3 в проекте.

Не храните реальные секреты в публичных репозиториях.

- `docker-compose.yml` (в корне): содержит сервисы `db` (Postgres) и `backend`.

## Краткое описание используемых сервисов и компонентов
Краткое описание компонентов и их ролей:

- `Postgres` (service `db` в `docker-compose.yml`): реляционная СУБД для хранения пользователей, отчётов, изображений и метаданных.
- `Backend` (`backend/`): API-сервер (FastAPI). Обрабатывает HTTP-запросы, логирует события, взаимодействует с БД и ML-адаптерами.
- `Frontend` (`frontend/`): SPA на Vite + Vue. В разработке запускается через `npm run dev`, в production собирается в статические файлы (`dist`).
- `Alembic` (миграции): управляет изменениями схемы БД; миграционные скрипты находятся в `backend/migration/versions`.
- `ML сервисы / модели`: модели и адаптеры расположены в `backend/ml_models` и `backend/ml_service`. Некоторые адаптеры поддерживают хранение артефактов в S3.
- `Docker volumes`: используются для персистентности данных Postgres (том `pgdata`).

Если функционал ML/S3 не используется — соответствующие переменные можно оставить пустыми, но связанный функционал будет недоступен.

## Инструкция по frontend
Директория фронтенда: `frontend/`.

A. Запуск dev-сервера (локальная разработка, требует Node.js >= 16):

```bash
cd frontend
npm install
npm run dev
```

Адрес dev-сервера выводится в консоли (обычно http://localhost:5173).

B. Сборка production-бандла:

```bash
cd frontend
npm install
npm run build
# результат в frontend/dist
```

C. Лёгкий локальный static server (для демонстрации):

```bash
npm install -g serve
serve -s frontend/dist -l 3000
# открытие на http://localhost:3000
```

D. Развёртывание frontend через Docker (nginx): добавить сервис `frontend` в `docker-compose.yml` как статический nginx, монтируя `frontend/dist`.

Примечание: фронтенд использует переменные окружения (Vite) — `VITE_API_URL` указывает на адрес backend (например, `http://localhost:8000`). Убедитесь, что при сборке переменная корректна.

## 4. Запуск (шаг за шагом)
Откройте терминал в корне проекта (папка, где находится `docker-compose.yml`).

Команды, которые нужно выполнить (подходит для Windows PowerShell, Git Bash, WSL, macOS и Linux):

```bash
# собрать и поднять контейнеры в фоне
docker compose up -d --build

# показать статус контейнеров
docker compose ps

# смотреть логи backend (в реальном времени)
docker compose logs -f backend
```

Примечание: в старых установках команда может называться `docker-compose` (с дефисом). Если `docker compose` не работает, попробуйте `docker-compose up -d --build`.

Подождите ~30–60 секунд, пока образы загрузятся и контейнеры запустятся.

## 5. Применение миграций базы данных (Alembic)
После запуска контейнеров нужно создать таблицы в базе (миграции). Это делается командой Alembic.

Выполните:

```bash
docker compose exec backend alembic upgrade head
```

Что такое миграции и зачем они нужны:

Миграции — это контролируемые изменения схемы базы данных: добавление таблиц, изменение колонок и т.д. Они позволяют плавно переносить структуру БД из одной версии приложения в другую, гарантируя, что у всех окружений одинаковая структура.

Что делает команда выше: она читает скрипты миграций в `backend/migration/versions` и применяет их последовательно — в результате создаются или изменяются таблицы, индексы и другие объекты БД.

Советы при проблемах:
- Подождите, пока контейнер `db` полностью поднят — иногда Postgres стартует дольше.
- Если миграции падают с ошибкой импорта, убедитесь, что в контейнере установлены все зависимости (`backend/requirements.txt`), включая `alembic` и драйвер для Postgres (`psycopg2-binary` или `asyncpg`).
- Для просмотра списка миграций используйте `alembic history` или `alembic current` (в контейнере или локально).

Примеры альтернативных запусков:

```bash
# выполнить миграции внутри запущенного контейнера
docker compose exec backend alembic upgrade head

# или запустить временный контейнер для миграций
docker compose run --rm backend alembic upgrade head

# локально (если установлен Python и зависимости)
cd backend
pip install -r requirements.txt
alembic upgrade head
```

## 6. Проверка сервиса (что показать заказчику)

- Откройте в браузере: http://localhost:8000/ — должен быть ответ (обычно пустой, зависит от реализации).
- Откройте документацию API (если есть): http://localhost:8000/docs
- Проверьте подключение к БД через любой клиент, например:

```bash
psql "postgresql://postgres:postgres@localhost:5432/cattle_db"
```

Если все доступно — развёртывание успешно.

## 7. Остановка и удаление контейнеров и данных

Остановить сервисы:

```bash
docker compose down
```

Удалить также данные (томы Postgres):

```bash
docker compose down -v
```

Внимание: `-v` удалит все данные в базе — используйте осторожно.

## 8. Быстрая проверка и отладка (частые проблемы)

- Посмотреть логи backend:

```bash
docker compose logs backend --tail=200
```

- Посмотреть полный список контейнеров и их статус:

```bash
docker compose ps
docker ps -a
```

- Если backend не подключается к БД: проверьте значение `DATABASE_URL` в `backend/.env` — в docker-compose host должен быть `db` (не `localhost`).

- Ошибка `ModuleNotFoundError` при старте: возможно, в `requirements.txt` не хватает пакета. Проверьте файл `backend/requirements.txt` и при необходимости добавьте нужный пакет, затем пересоберите образ:

```bash
docker compose build backend
docker compose up -d
```

## 10. Замечания для production

- В production не использовать `--reload` и монтирование исходников в контейнер (`volumes`), вместо этого запускать оптимизированные образы без dev-зависимостей.
- Использовать процесс-менеджер / WSGI сервер (gunicorn/uvicorn workers) и reverse-proxy (nginx) для TLS и статических файлов.
- Хранить секреты в менеджере секретов (Vault, AWS Secrets Manager) или в CI, а не в `.env` в репозитории.
- Организовать резервное копирование тома Postgres и мониторинг (healthchecks, логирование).
